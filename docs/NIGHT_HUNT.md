# NIGHT HUNT · 夜猎

一个独立的月夜交锋短篇。入口：[`#/night-hunt`](https://gongsheng16435.github.io/qiantai/#/night-hunt)。LUMEN 首页与主导航均有入口，原有游戏档案保持独立。

## 三招，一场狩猎

| 操作 | 键鼠 | 机制 |
| --- | --- | --- |
| 移动 | WASD / 方向键 | 在钟庭地面自由移动，鼠标指向决定朝向 |
| 挥刃 | 左键，可按住 | 消耗 13 精力，三段连击伤害 25 / 25 / 34；架势崩解后的第一击伤害 180 |
| 闪避 | 空格 | 消耗 25 精力；无方向输入时向远离 Boss 的方向闪避；无敌窗 0.32 秒 |
| 弹反 | E / 右键 | 消耗 18 精力，朝向敌人，判定窗 0.22 秒；只对可弹反攻击有效 |
| 血瓶 | Q / 生命条下的血瓶按钮 | 每局 2 瓶，每瓶恢复最大生命的三分之一；满血不消耗，恢复量不超过生命上限 |
| 暂停 | Escape / 暂停按钮 | 保持当前交锋，切出窗口也会暂停 |

触控：左侧摇杆移动，右侧三枚按钮释放招式，挥刃自动朝向 Boss；生命条下的血瓶按钮可点按使用。横屏可获得完整的场景构图。页面保留静音与全屏控制，原生全屏依浏览器支持情况启用。

精力上限 100，停手后每秒回复 28。成功弹反增加 27 点 Boss 架势，恢复 28 精力与 4 生命；在闪避最初 0.20 秒接住攻击判定为完美闪避，恢复 22 精力与 2 生命。架势到 100 时，Boss 失衡 3 秒，可挥刃追击一次。血瓶不消耗精力，每瓶恢复 100/3 生命，倒下或主动重开后恢复为 2 瓶；暂停、死亡和胜利时无法使用。

## 钟骸守望者

Boss 共 5400 生命。第一阶段包含横扫、突刺和不可弹反的重砸。攻击在落下之前给出地面轮廓与音响预警，突刺在蓄力前半段锁定方向。

生命降至一半进入第二阶段：月蚀、灰烬、暗红色裂纹、节奏更紧的配乐，同时增加连续横扫和重砸后的扩散冲击波。转阶段有 2.2 秒停顿，猎人恢复 25 生命与全部精力，给出重新站位的时间。胜利后显示用时、弹反与完美闪避次数。死亡 0.95 秒后自动重开，保留当前会话的失败次数。离开游戏后不保存战斗进度。

时长按谨慎进攻的约 3–6 分钟设计，不使用强制拖延或不可跳过的循环。自动化完整生命值模拟中，熟练进攻约 124–138 秒；控制出手频率并包含防御失误的模拟约 201–206 秒。实际时长取决于熟练程度，失败回合可能很短。

## 技术与素材

- React 管理封面、HUD、暂停、结算和触控，状态快照约 10 Hz 更新。
- 点击 PLAY 后才动态导入 Phaser 3.90.0。逻辑画布 1600 × 900，FIT 缩放，优先 WebGL，可回退 Canvas。地面边界为 x=70–1530、y=470–810，可移动面积较初版扩大约 77%；角色和攻击范围保持原来的世界单位，使实际可绕行空间增大。背景与月蚀层同步适配扩大的画布。
- `NightHuntScene.ts` 管理战斗状态与判定；`renderer.ts` 管理线描角色、月亮、建筑、前后景、粒子与预警。地面判定与绘制共同使用 0.55 的纵向压缩比例。
- 静态背景纹理只生成一次。封面 SVG、角色与场景均为项目原创的程序化线描，没有引用其他游戏的专有图像。
- `audio.ts` 使用 Web Audio 振荡器、噪声、滤波与压缩合成音乐和音效，没有外部音频文件。暂停、静音与销毁分别处理，离开游戏关闭 AudioContext。
- `prefers-reduced-motion` 关闭震屏、强闪光、封面缩放及装饰性晃动，保留辨识攻击所需的动画与时间机制。
- 哈希路由、相对资源路径沿用 GitHub Pages 部署配置，无 API 密钥与新增后端依赖。

参考了 [Phaser 官方 React / TypeScript 集成说明](https://github.com/phaserjs/template-react-ts)、[Phaser 3 文档](https://github.com/phaserjs/phaser/tree/v3.90.0) 与 [MDN AudioContext 文档](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext)。这里只采用框架与生命周期的技术方式；游戏规则、美术和音乐在本项目中实现。

## 验证

运行 `npm run build` 检查 TypeScript 并生成生产包。开发服务器为 `npm run dev -- --host 0.0.0.0`。

开发时在真实 Chromium 中验证了完整页面流程、鼠标 / 键盘输入、触屏布局、暂停和恢复、返回封面后销毁、重复进入、声音开关、音频生命周期以及无控制台异常。另通过仅在开发浏览器中导入场景的临时脚本，验证伤害与精力、弹反时机、完美闪避、不可弹反攻击、架势破坏与处决、转阶段、冲击波、死亡重开与胜利。生产代码没有暴露测试或作弊入口。

布局检查覆盖桌面、手机竖屏及横屏。移动端以浏览器设备模拟验证，尚未进行实体手机的声音与性能测试。浏览器的低功耗策略、原生全屏和 Web Audio 支持会影响不同设备的表现。
